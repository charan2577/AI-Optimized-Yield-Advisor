# Technical Documentation: AI-Optimized Yield Advisor
### Architecture, Mathematical Formulations, and MLOps Governance

---

## 1. Architectural Topology

The AI-Optimized Yield Advisor follows a hybrid deployment model designed for high-throughput semiconductor manufacturing:

1. **Edge Ingestion Tier (Tester Cell)**:
   - Real-time STDF V4 tailing as binary test records are generated by Advantest or Teradyne ATE probers.
   - Low-latency inference (<1s/die) for dynamic stop-on-fail alarms and probe needle contact resistance tracking.
2. **Lakehouse Storage & Feature Store**:
   - Time-travel capable tabular storage (Parquet/Delta) partitioned by `product`, `lot_id`, and `stage` (`CP1`, `CP2`, `FT`).
   - Feature store maintaining normalized spatial moments, fab metrology aggregates, and tool genealogy.
3. **Analytical & Model Serving Tier**:
   - Batch scoring triggered at wafer unload (<2 min post-sort) for spatial pattern classification and DPAT outlier inking.
   - Lot-end evaluation (<15 min post-lot) for EWMA/CUSUM excursion detection and commonality root-cause attribution.
4. **Advisory Cockpit & Human Governance**:
   - Streamlit multi-page interface exposing interactive Plotly analytics, evidence packs, and CCB approval workflows.

## 3. Mathematical & Algorithmic Formulations

### 3.1 Random vs Systematic Yield Separation (Negative Binomial Model)
The total sort yield $Y_{\text{sort}}$ is factorized into systematic yield $Y_{\text{sys}}$ and random-defect yield $Y_{\text{rand}}$:
$$Y_{\text{sort}} = Y_{\text{sys}} \cdot Y_{\text{rand}}$$
Under defect clustering, $Y_{\text{rand}}$ follows the Negative Binomial model:
$$Y_{\text{rand}} = \left(1 + \frac{A \cdot D_0}{\alpha}\right)^{-\alpha}$$
where $A$ is the critical chip area ($\approx 0.75\text{ cm}^2$), $D_0$ is the random defect density ($\approx 0.10/\text{cm}^2$), and $\alpha$ is the defect clustering parameter. As $\alpha \to \infty$, the distribution converges to the classical Poisson model $e^{-A D_0}$.

### 3.2 Statistical Process Control (EWMA & CUSUM)

#### Exponentially Weighted Moving Average (EWMA)
For chronological lot yields $X_1, X_2, \dots, X_t$, the EWMA statistic $Z_t$ is defined as:
$$Z_t = \lambda X_t + (1 - \lambda) Z_{t-1}, \quad Z_0 = \mu_0$$
where smoothing factor $\lambda = 0.20$. The exact time-varying statistical control limits are:
$$\text{UCL}_t / \text{LCL}_t = \mu_0 \pm L \cdot \sigma_0 \sqrt{\frac{\lambda}{2 - \lambda} \left[1 - (1 - \lambda)^{2t}\right]}$$
with $L = 3.0$. EWMA provides an In-Control Average Run Length ($\text{ARL}_0$) of $\approx 500$ lots while detecting a $1.5\sigma$ shift within $\le 3$ lots.

#### Cumulative Sum (CUSUM) Downward Shift Detection
$$C_t^- = \max\left(0, (\mu_0 - K) - X_t + C_{t-1}^-\right), \quad C_0^- = 0$$
where reference parameter $K = 0.5 \sigma_0$ and decision threshold $H = 4.5 \sigma_0$. An excursion alarm signals whenever $C_t^- > H$.

### 3.3 AEC-Q001 Dynamic Part Average Testing (DPAT)
Following automotive standard AEC-Q001, dynamic outlier thresholds are computed per wafer using robust non-parametric estimators:
$$\text{robust\_mean} = \text{median}(x)$$
$$\text{robust\_sigma} = \frac{\text{IQR}}{1.35} = \frac{Q_3 - Q_1}{1.35}$$
$$\text{DPAT Limits} = \left[\max\left(\text{LSL}, \text{median} - k \cdot \text{robust\_sigma}\right), \; \min\left(\text{USL}, \text{median} + k \cdot \text{robust\_sigma}\right)\right]$$
with $k = 6.0$. Outliers passing normal specification limits [40 μA, 65 μA] but violating dynamic limits are flagged for electronic inking.

### 3.4 Good-Die-in-Bad-Neighborhood (GDBN)
For each passing die $d(x,y)$, the 8-connected Moore neighborhood $N_8(d)$ is evaluated:
$$\text{NBF}(d) = \sum_{(dx, dy) \in \{-1,0,1\}^2 \setminus \{(0,0)\}} \mathbb{I}\left[\text{die}(x+dx, y+dy) \text{ failed}\right]$$
If $\text{NBF}(d) \ge 5$, the passing die is flagged as high-risk latent defect due to defect clustering proximity.

### 3.5 Rule-of-Three Statistical Escape Risk Bound
When evaluating whether a test item (e.g. `RING_OSC` or `ADC_INL`) can be transitioned to audit sampling, the risk of test escape is bounded using the classical **Rule of Three**.
For zero unique failures observed in $N$ tested dies, the 95% upper confidence bound on the true escape rate $p$ is:
$$p_{95\%} \le \frac{3}{N}$$
Expressing this in Defective Parts Per Million (DPPM):
$$\text{DPPM}_{\text{upper}} = \frac{3}{N} \times 10^6$$
For the benchmark population of $N = 500,000$ dies:
$$\text{DPPM}_{\text{upper}} = \frac{3}{500,000} \times 10^6 = 6.0 \text{ DPPM}$$
Under a 5% continuous QA audit sampling scheme, any active process shift is guaranteed to be detected before significant volume escapes.

## 4. Multi-Factor Commonality & Causal Guardrails

To separate statistical association from spurious correlation:
1. **Contingency Testing**: 2x2 contingency tables are built for every tool and chamber:
   $$\text{Odds Ratio} = \frac{A / B}{C / D}, \quad \text{Fisher Exact Test } p\text{-value}$$
2. **Continuous Distribution Testing**: Kruskal-Wallis non-parametric ANOVA on wafer yield distributions across tool groupings:
   $$H = \frac{12}{N(N+1)} \sum_{i=1}^k \frac{R_i^2}{n_i} - 3(N+1)$$
3. **Causal Attribution Guardrail**: Recommendations output by the engine are explicitly tagged as:
   - `Statistical Association (High Excursion Correlation)`: Requires validation through split-lot or tool-down inspection.
   - `Parametric Root Cause (WAT to Sort Correlation)`: Supported by direct physical semiconductor device physics (e.g. $V_{t\_n}$ drift raising $V_{\min}$ and lowering $F_{\max}$).

## 5. Human-in-the-Loop Governance & MLOps Lifecycle

### Autonomy Levels
- **Level 0 (Inform)**: Dashboards and charts display raw statistics.
- **Level 1 (Advise - Active Production Standard)**: AI engines generate prioritized recommendations with quantified dollar benefits and risk bounds. Human engineers review and approve through CCB.
- **Level 2 (Auto-Execute - Pre-Approved Policy Only)**: Limited exclusively to pre-approved automated second-insertion retests for probe contact bins (SB30).

### Drift Monitoring
- Models are tracked using Population Stability Index (PSI):
  $$\text{PSI} = \sum \left(P_{\text{actual}} - P_{\text{expected}}\right) \cdot \ln\left(\frac{P_{\text{actual}}}{P_{\text{expected}}}\right)$$
  A PSI $> 0.25$ triggers automated notification for model recalibration.
- Test program revision (`program_rev`) is treated as a hard schema boundary; new revisions require shadow validation before production deployment.
